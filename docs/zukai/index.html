① 作ったもの

1人で続けるための、3本の導線

学習法の主張は「必要なのは2つだけ」。受け取ると作り出す、そしてその2つを繋ぐ。アプリはこれをそのまま3本の柱にした。

瞬間英作文 — 日本語を見た瞬間に、英語を作る

毎日使ううちに、穴が見えた。100 を受け取っても、0 からは出てこない。日本語で考えて詰まるなら、そこだけ別に鍛えればいい——動画の方法論には無いが、自分で1本足した。日本語が出る → 考える時間 → 答えを表示して読み上げ → 声に出して再現 → 次へ。★を付けた文だけを流せるので、言えるものは飛ばせる。

③ 作りたいと思った理由

続かない、ではなく「始められない」だった

きっかけは1本のYouTube動画だった。「英語が話せなかった私が1年未満でペラペラになったたった1つの方法」。語られる学習法——完成された英語を100のまま受け取り、0から独り言で作り出す——は、これまで試したどの教材よりも説得力があった。これをやれば英語は伸びる。素直にそう思えた。

これをやれば伸びる——そう思えたのに、
始めることすら、できなかった。

よく言う「三日坊主で続かない」より、もっと手前だった。普段はPCとスマホでしか作業しない自分に、紙に書き出す習慣も、カラーペンも無い。「紙を用意して、行間を空けて、7色で音を書き込む」——その最初の一歩が面倒すぎて、踏み出せなかった。

面倒はそこだけではなかった。自分に合った動画を探す、練習する区間を選ぶ、その区間を何度も再生する、自分の声を録る、覚えたフレーズを書き留める——シンプルな勉強に見えて、手が止まる場所が無数にあった。続かないのは意志の弱さだと思っていたが、正体はこの小さな面倒の積み重ねのほうだった。

だから、意志で乗り越えるのをやめて、面倒のほうを消すことにした。動画を探すところから、区間を選ぶ・繰り返し再生する・声を録る・フレーズを書き留めるまで——学習が止まる理由を一つずつ、道具の側で潰していく。紙もペンもChatGPTも、1つのアプリに畳み込んだ。すごいものを作りたかったわけではない。毎日、ストレスなく始められて、そのまま続く。それだけを狙って作った。

④ 工夫と苦戦

作ってみて気づいたこと

学習法への忠実さと、ブラウザという実行環境の現実。その両方に、いくつも手を入れることになった。

工夫止まる理由を、仕組みで消す

面倒を減らし、「続く」までを設計した。

  • 手が止まる場所を、そのまま機能にした動画を探す・区間を選ぶ・繰り返し再生する・声を録る・フレーズを残す——③で数えた「止まる場所」を一つずつ操作に翻訳。URLを貼る／A-Bで切り出す／1回再生して止める／ワンタップ録音。紙もカラーペンも要らない。
  • AIをアプリに畳み込み、行き来をなくした音の解析・分からない箇所の解説・独り言の英語化・使えるフレーズの抽出——ChatGPTへコピペしていた作業を、他ツールへ移らずアプリ内で完結。LLMが不安定な数値位置を返さないよう quote＋出現回数 で復元するなど、精度も作り込んだ。
  • 減らすだけでなく、「続く」を可視化した面倒を消すだけでは続かない。連続日数・12週ヒートマップ・再現回数・独り言の合計時間を常に見せ、やった事実を積み上げる。測るのは「聴いた回数」ではなく 言えた回数。独り言は音声を残さず時間だけを刻む——可視化のための記録だから。
  • 使ってみて空いた穴を、自分で足して埋めた毎日回すうちに「100 を受け取っても 0 から出てこない」と分かり、瞬間英作文を方法論の外から足した。答えを飛ばす手段は持たせない——日本語 → 口に出す → 直後に答え、の順を崩さないため。★ は「まだ言えない」印で、言えたら外す。素材も動画に縛らず、自作テキストをTTSで1文ずつ読ませて同じワークスペースに載せた。

苦戦環境が返してきた現実

「動くはず」が動かない罠を、1つずつ踏んだ。

  • iOS Safari の録音は audio/mp4audio/webm 決め打ちだと無音。isTypeSupported で分岐してようやく実機で録れた。
  • getUserMedia が無反応で返らないマイク許可が返ってこないと無反応のボタンが残る。15秒でタイムアウトし、理由を出すようにした。
  • YouTube IFrame の end はループしない区間ループが素直に作れず、requestAnimationFrame で終端を監視して seekTo で戻す実装に。
  • 選択がボタン押下で消える記号を付ける前に選択範囲が解除される。ツールバーは onMouseDown で preventDefault()。
  • 読み上げの固着から、クラウドTTS移行と本番の落とし穴までブラウザ標準の speechSynthesis は使ううちに声はあるのに start が来ず無音で固着し、リロードでは戻らずブラウザ再起動が必要だった。延命策では回復しきれないと判断し、サーバで音声を生成 → <audio> で再生 → キャッシュするクラウドTTSへ全面移行。すると今度は本番の保存が三段の罠に阻まれた——upload() に ArrayBuffer を渡すと壊れ、Storage の RLS は to authenticated が効かず auth.uid() 判定が要り、SSR サーバはユーザーの認証を Storage に載せられずサーバ専用の service role キーで保存する必要があった。最後は本番だけ Invalid Compact JWS で弾かれ、新形式キーではなく eyJ… の legacy JWT が要ると突き止めて解決した。
  • 一時停止と再開が、端末ごとに壊れるpause()／resume() は端末差が大きく当てにできない。読み上げ中に止めたら cancel() してその文を頭から読み直す設計に。考える時間はCSSアニメを凍結し、performance.now() の締切から残りを割り出して張り直す。

何を作ったかより、
なぜ作ったか。

毎日の面倒から生まれたこの道具は、それ自体が自分にしか語れない物語になった。本気で最後まで作り上げることに勝る学びはない。
